# iccIisIsapi API Reference

This document covers the externally callable HTTP surface and native IIS ISAPI
exports for `iccIisIsapi.dll`. Setup and deployment instructions are in
[isapi-instructions.md](isapi-instructions.md).

Machine-readable starter spec: [iis-isapi.openapi.yaml](iis-isapi.openapi.yaml).

## Scope

Documented here:

- `iccIisIsapi.dll` HTTP endpoints
- capability-style `_tool-work` artifact endpoints
- native IIS ISAPI exports: `GetExtensionVersion`, `HttpExtensionProc`,
  `TerminateExtension`

Not documented here:

- full C++ API surface of `IccProfLib`, `IccLibXML`, or `IccLibJSON`
- every CLI option outside the IIS-wrapped tool flow

## Base Assumptions

- The sample is Windows-only.
- IIS maps `iccIisIsapi.dll` through `IsapiModule`.
- The handler receives every verb and returns controlled 405 responses for
  methods other than the documented `GET` and `POST` operations.
- The site root contains required runtime DLLs and wrapped tool executables.
- The default IIS binding is loopback-only.
- `_tool-work` retains at most 100 jobs for 24 hours and denies its root.

## HTTP API

### `GET /iccIisIsapi.dll`

Default summary response.

- Status: `200 OK`
- Content type: `text/plain; charset=utf-8`
- Body includes the service name, profile spec version, XML payload byte count,
  and greeting text. It does not include library versions or commit hashes.

### `GET /iccIisIsapi.dll?mode=health`

Health probe for smoke tests and monitoring.

- Status: `200 OK`
- Content type: `text/plain; charset=utf-8`
- Body: `ok`

### `GET /iccIisIsapi.dll?format=xml`

Returns a minimal ICC XML payload generated in-process.

- Status: `200 OK`
- Content type: `application/xml; charset=utf-8`

### `GET /iccIisIsapi.dll?format=json|fromjson`

Returns documented structured endpoint or optional JSON round-trip metadata.
Library versions and commit hashes are not included.

### `POST /iccIisIsapi.dll?mode=tools&input=icc|xml[&filename=...]`

Runs the browser tool suite against uploaded ICC or XML data.

Supported request bodies:

- `application/octet-stream` for ICC or ICM uploads
- `application/xml` or `text/xml` for XML uploads

Required request header:

- `X-ICCDEV-Request: 1`

The custom header prevents a cross-site HTML form from launching the tool
pipeline. Requests marked `Sec-Fetch-Site: cross-site` are also rejected.

Query parameters:

| Parameter | Required | Values | Purpose |
|-----------|----------|--------|---------|
| `mode` | yes | `tools` | Select wrapped tool pipeline |
| `input` | yes | `icc`, `xml` | Uploaded data type |
| `filename` | no | sanitized base name | Response metadata; the server forces `.icc` or `.xml` |

Current upload limit: `16 MB`.
Maximum active tool requests: `4`.

Unknown `mode` or `format` values, conflicting selectors, and encoded null
bytes are rejected with HTTP 400 instead of falling through to the summary.

For `input=icc`, the handler writes the upload to a per-request workspace and
runs `iccToXml`, `iccFromXml`, `iccDumpProfile`, `iccPawgReport`,
`iccRoundTrip`, and JSON tools when available.

For `input=xml`, the handler writes the upload as XML and runs `iccFromXml`,
`iccDumpProfile`, `iccPawgReport`, `iccToXml`, `iccRoundTrip`, and JSON tools
when available.

`iccPawgReport` exit code `1` means the report completed with one or more
findings. The IIS response therefore marks that tool result as completed,
includes a note about the findings, and persists `icc-pawg-report.txt` for
download.

The HTTP response is `200 OK` when the request is accepted and processed. Each
wrapped tool reports its own `exit_code`, `ok`, `skipped`, `output`, and artifact
links.

## Tool-Suite Response Shape

Top-level fields:

| Field | Meaning |
|-------|---------|
| `mode` | Always `tools` |
| `input.kind` | `icc` or `xml` |
| `input.filename` | sanitized workspace filename |
| `input.bytes` | uploaded byte count |
| `input.url` | relative URL for persisted upload |
| `workspace_url` | relative URL for request workspace |
| `tools` | per-tool result array |

Per-tool fields:

| Field | Meaning |
|-------|---------|
| `name` | wrapped tool name |
| `exit_code` | process exit code, or `-1` when skipped or launch failed |
| `ok` | true for an accepted completed result; normally exit `0`, plus PAWG exit `1` when findings were reported |
| `skipped` | true when intentionally skipped |
| `note` | timeout or skip reason |
| `output` | captured output, truncated for browser display when needed |
| `log_url` | relative URL for persisted log |
| `artifact_url` | relative URL for generated artifact |
| `artifact_preview` | text preview when available |

## Persisted Artifacts

Per-request workspaces live under `_tool-work/<128-bit-job-id>/`. Each job ID
contains 128 bits generated by the Windows system cryptographic random number
generator. Directory browsing is disabled and the workspace root has no index;
callers receive only their capability URL in their own response.
A workspace can contain:

- uploaded input
- stdout/stderr logs
- generated ICC, XML, or JSON artifacts
- downloadable `icc-pawg-report.txt`
- `index.html` for browser navigation

Workspaces expire after 24 hours, with a maximum of 100 retained jobs. Static
responses include CSP, clickjacking, MIME-sniffing, referrer, and no-store
headers. The CSP blocks style attributes and permits only same-origin
stylesheets plus exact hashes for the three served inline stylesheet blocks;
it does not enable `unsafe-inline`.

IIS-generated 403 and 404 responses use `error.html` and do not expose physical
paths, handler mappings, authentication methods, or detailed diagnostics.

The loopback deployment uses capability URLs for local QA. Any non-loopback
deployment must add IIS authentication and authorization rather than treating
capability URLs as the sole access-control layer.

XML uploads containing a `DOCTYPE` declaration are rejected before tool
execution.

## Native ISAPI Exports

| Export | Purpose |
|--------|---------|
| `GetExtensionVersion` | Reports extension version and description to IIS |
| `HttpExtensionProc` | Handles each request |
| `TerminateExtension` | Performs extension shutdown |

## Examples

```powershell
curl.exe http://localhost:18081/iccIisIsapi.dll?mode=health
curl.exe http://localhost:18081/iccIisIsapi.dll?format=xml
curl.exe -H "Content-Type: application/octet-stream" `
  -H "X-ICCDEV-Request: 1" `
  --data-binary "@sample.icc" `
  "http://localhost:18081/iccIisIsapi.dll?mode=tools&input=icc&filename=sample.icc"
```
